## Conclusion

- **Query translation fixed the cross-language problem.** English questions on German docs went from 1.5/5 to 4/5, the same level as asking in German. E4 and E8 found the right page only through the German translation ("via:" lines).
- **Cost:** retrieval went from ~50 ms to ~3.5 s because of the extra LLM call. Total time per question now ~9–10 s.
- **The bottleneck has moved to the answer step.** Retrieval is now good, but the 7B model breaks rules: it adds "not in the documents" after a correct answer (E4), answers in German to English questions (E6), and once used outside knowledge with a wrong citation (#6).
- **Bug found and fixed:** the model sometimes returned both translations on one line (#6, #7, E8), so only one combined query was searched. The parser now splits them.
- **#7 / E7 still fail.** The course-deregistration rule (Anmeldeverordnung p. 6) never shows up; "abmelden" matches the KUSSS *exam* deregistration sheet more strongly. Candidate for hybrid search or a reranker.

## Next ideas
- Answer step: stricter prompt (language, no extra sentences), or a stronger LLM via API for comparison
- Faithfulness check: does every claim appear in the retrieved text? (#6 shows answers can look right but be ungrounded)
- Speed: run the original search while translating, or only translate when the question isn't German
